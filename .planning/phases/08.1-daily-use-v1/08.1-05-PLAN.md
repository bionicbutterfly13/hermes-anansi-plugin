<objective>
Route Anansi's appraisal through its own host auxiliary task so chief-of-staff can run it on gpt-6-sol while reflection stays on the main model (D-06).

Purpose: the host now lets a plugin own an `auxiliary.<key>` config slot and pass `task=` on calls, with no trust override; that is the supported way to pick a model per task.

<interfaces>
Host contracts (hermes-agent 0.21.4, verified at planning time; re-read before coding because 08.1-02 may re-sync the host):
- `ctx.register_auxiliary_task(key, *, display_name, description, defaults=None)` in `hermes_cli/plugins.py`: raises `ValueError` for an invalid key, a built-in key, or another plugin's key; defaults merge to provider `auto`, timeout 60; user config wins over plugin defaults.
- `PluginLlm.complete_structured(..., task=None)` in `agent/plugin_llm.py`: `_check_task` returns None for unset/empty/`auto`, allows a key the plugin registered (ownership read lazily from `hermes_cli.plugins.get_plugin_auxiliary_tasks()`), and raises `PluginLlmTrustError` for anything else. The call kwargs handed to the sync caller include `task`.
- An explicit per-call `timeout` beats `auxiliary.<task>.timeout`, so the plugin's 8.0s deadline still binds. A requested `model=` (from `plugins.entries.anansi.llm.model`) beats the task's configured model.
- Hosts older than this API have no `task` parameter on `complete_structured`, so passing `task` unconditionally would raise `TypeError` there.
</interfaces>
